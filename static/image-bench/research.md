# 이미지 벤치 조사와 이번 비교의 설계

2026-10-09 기준 공식 논문·코드·제품 문서를 확인했다. 연구의 대규모 평가를 그대로 실행한 것이 아니라, 평가 방법을 참고해 카페 이야기로 만든 소규모 자체 벤치다.

## 다른 사람들은 어떻게 비교했나

| 사례 | 실제 방법 | 이번 비교에 가져온 부분 |
|---|---|---|
| [GenEval](https://github.com/djghosh13/geneval) | 물건, 개수, 위치, 색 같은 구체적인 조건을 물체 탐지로 검사한다. 공개 생성 예제는 프롬프트당 4장을 만들고, 평가 결과에 정답 여부와 이유를 저장한다. | 장면 02에서 컵 3개·색의 위치·꽃 5송이를 각각 확인한다. |
| [GenEval 2 / Soft-TIFA](https://github.com/facebookresearch/GenEval2) | 800개 프롬프트에 질문·정답과 능력 항목을 붙인다. VQA 모델로 각 질문의 정답 확률을 평가한다. | 모든 프롬프트를 눈으로 확인할 수 있는 체크 항목으로 분해한다. Soft-TIFA 자동 점수는 사용하지 않는다. |
| [HEIM, NeurIPS 2023](https://arxiv.org/abs/2311.04287) | 지시 준수, 품질, 미감, 다국어, 효율 등을 포함한 12가지 측면을 62개 시나리오와 26개 모델로 평가한다. 이미지와 사람 평가를 공개한다. | 미감 선호와 요구사항 충족을 구분하고, 원본·시간·프롬프트를 함께 공개한다. |
| [Arena Image Battle](https://help.arena.ai/articles/1626988163-lmarena-how-to-use-image-generation) | 같은 프롬프트로 만든 익명 모델 두 개의 결과를 보여 주고 사람의 선호 투표를 받는다. | 모델명을 가리는 A/B 비교와 좌우 변경을 제공한다. 로컬 사용자 투표를 공식 Arena 순위로 바꾸지 않는다. |

핵심은 ‘예쁜가’와 ‘시킨 대로 만들었나’를 별도로 보는 것이다. 작은 글자를 정확히 그린 이미지와 자연스러운 사진이 같은 모델에서 항상 나오지는 않을 수 있다. 그래서 전체 모델 순위 하나 대신 장면별로 결과를 보여 준다.

## 대중이 이해하기 쉬운 이야기

**동네 카페가 봄맞이 영업을 준비하는 하루**를 네 장면으로 구성한다. 각 프롬프트는 한국어 세 문장이며, 세 모델에 같은 문자열을 보낸다. 생성 전에 모델별로 번역하거나 프롬프트를 고치지 않는다.

| 순서 | 장면 | 관객에게 던질 질문 | 왜 넣었나 |
|---|---|---|---|
| 1 | 아침 햇살 속 유리잔과 크루아상 | 유리와 빵의 결, 그림자가 자연스러울까? | 고해상도 숫자와 실제 재질 표현을 함께 보기 위해 |
| 2 | 컵 세 개와 튤립 다섯 송이 | 개수와 색, 위치를 제대로 지켰을까? | 눈으로 세고 바로 판단할 수 있는 지시 준수 검사 |
| 3 | 봄맞이 한글 포스터 | 한글과 3,500원 가격이 정확히 읽힐까? | 한국어 사용자의 실무 품질 검사 |
| 4 | 바리스타가 첫 커피를 따르는 순간 | 손·주전자·커피 줄기가 제대로 이어질까? | 물리적 연결과 손 표현 검사 |

복잡한 판타지나 많은 인물 없이 일상 물건으로 비교한다. 장면별 검사 질문, 내레이션, 6초 길이, 확대할 상대 위치를 `motion_manifest.json`에 저장한다. 4장면 24초의 비교 영상에 옮길 수 있지만, 현재 납품물은 대시보드이며 영상 렌더는 별도 단계다. 서로 독립적으로 생성한 장면이므로 같은 카페·사람을 유지하는 연속 일관성 벤치는 아니다.

## 최대 해상도와 공정한 표시

- OpenAI 최신 두 모델: 날짜 고정 모델 ID, `size=3840x2160`, `quality=max`, PNG. 공식 문서는 2.5 모델의 최대 픽셀 수를 8,294,400으로 설명하며, 2560×1440을 넘는 크기는 실험적이라고 표시한다. [OpenAI 생성 문서](https://developers.openai.com/api/docs/guides/image-generation)
- Google Nano Banana 2.1: `aspectRatio=16:9`, `imageSize=4K`. 공식 표의 예상 크기는 5504×3072다. 실제 반환 파일을 디코딩해 크기를 검증한다. [Google 생성 문서](https://ai.google.dev/gemini-api/docs/image-generation)
- 이번 목표는 각 모델의 최대 가로형 원본 생성이다. 같은 계산량이나 같은 해상도로 제한한 성능 비교와 구분한다.
- 대시보드의 ‘전체 보기’는 같은 화면 크기에서 감상하는 비교다. ‘원본 100%’는 이미지 1픽셀을 1 CSS 픽셀로 표시한다. 이미지의 위치는 서로 다르므로 두 그림이 정확히 정렬된다고 가정하지 않는다.
- 원본에 업스케일이나 선명화 처리를 하지 않는다. API의 반환 파일 그대로 저장하고 SHA-256과 실제 크기를 기록한다.

## 검토 기준과 한계

1. 각 장면·모델의 최초 성공 응답 1장을 사용한다. 좋은 결과를 골라 다시 만들지 않는다.
2. 체크 항목은 관찰 가능한 요구사항만 판정한다. `true`는 충족, `false`는 불충족, `null`은 눈으로 확정하기 어려운 항목이다. 가려진 손가락이나 유리잔의 수위처럼 애매한 점을 확정으로 쓰지 않는다.
3. 작성자 검토는 AI가 이미지를 보고 적은 관찰이다. 사람 다수의 독립 평가가 아니다. 사용자의 체크와 메모는 별도로 저장한다.
4. 미감 선호 투표는 요구사항 체크와 합쳐서 총점으로 만들지 않는다. 다수의 독립 투표가 없으므로 Elo나 일반적 우승 모델을 계산하지 않는다.
5. 모델당 4장의 결과로 일반 성능이나 반복 안정성을 결론 내릴 수 없다. 연구 수준 평가로 확장하려면 프롬프트당 반복 생성과 여러 평가자가 필요하다.
6. API 실패가 있으면 실패 증거도 보존한다. 자동으로 품질을 낮추거나 모델을 바꾸지 않는다. 요청 ID, 시간, 사용량이 있으면 저장한다. 실제 청구 금액은 과금 콘솔 확인 없이 추정값을 확정액이라고 부르지 않는다.
7. OpenAI는 요청한 고정 ID를 기록한다. 응답에 모델 버전이 없으면 ‘응답에 없음’으로 표시한다. Google은 응답의 `modelVersion`도 기록한다.

## 재현

환경변수 `OPENAI_API_KEY`와 `GEMINI_API_KEY`를 설정한 셸에서 프로젝트 안의 가상환경으로 `generate.py`를 실행한다. 키 값은 출력하거나 증거에 저장하지 않는다.

```sh
../.venv/bin/python generate.py --models sunburst,flare,nano21
python3 build.py
python3 -m http.server 8765 --bind 127.0.0.1 --directory ..
```

이미 생성 기록이 있는 요청은 다시 생성하지 않는다. 성공·실패·진행 중 상태를 모두 보존하므로 실수로 중복 청구되는 일을 줄인다. 새 반복 실험은 별도 실행 폴더로 진행해야 한다. 대시보드는 `http://127.0.0.1:8765/benchmark/`에서 열린다.
